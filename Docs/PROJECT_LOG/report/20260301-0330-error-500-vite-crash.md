# Hata Çözüm Raporu: 500 Server Error ve Vite Çökmesi

## Tarih: 2026-03-01
## Kategori: Hata Çözümü (Error Handler)
## Konu: Laravel Vite Entegrasyonu Kaynaklı 500 Hatası

### 1. Hatanın Tanımı
"500 Server Error" hatası alındı. `storage/logs/laravel.log` dosyasına herhangi bir yeni hata düşmüyor, `APP_DEBUG=true` olmasına rağmen standart Tailwind CSS ile biçimlendirilmiş siyah bir 500 hata sayfası dönüyordu.

### 2. Analiz Süreci
- Laravel'in kendi log dosyaları kontrol edildi (`storage/logs/laravel.log`). Hata görünmeyince uygulamanın kendisinin hatasız çalıştığı (`php artisan view:cache` komutuyla) tespit edildi.
- Sorunun request sırasında, görünümler render edilirken oluştuğu anlaşıldı.
- Docker logları incelendi (`cadde1905_app` ve `cadde1905_node`). Node (Vite) konteyner loglarında aşağıdaki hata bulundu:
  ```
  Error: Package subpath './vite' is not defined by "exports" in /var/www/node_modules/tailwindcss/package.json
  ```
- Sorunun Kaynağı: `vite.config.js` dosyasında Tailwind v4 paketi doğru ayarlanmış olsa da, `cadde1905_node` isimli Docker konteynerinin bu yapılandırmayı (ve paket güncellemelerini) yeniden yüklemediği (Eski versiyonda veya crash durumunda takılı kaldığı) tespit edildi. Vite sunucusu çalışmadığında, Laravel'in `@vite` direktifi assetleri çözemediği için doğrudan bir Fatal Exception fırlatarak 500 hatasına neden oluyordu.

### 3. Çözüm
- `cadde1905_node` (Vite) konteyneri yeniden başlatıldı:
  ```bash
  docker-compose restart node
  ```
- Konteyner yeniden başlatıldıktan sonra güncel `vite.config.js` yapılandırmasını algılayıp `VITE v7.3.1` olarak başarıyla başlatıldı ve `Network: http://172.18.0.2:5173/` adresi üzerinden dosyaları sunmaya başladı.
- Node konteyneri ayağa kalktıktan sonra yapılan Curl testi ile anasayfanın başarıyla ("CADDE1905" Title ile) 200 OK yanıtı döndürdüğü doğrulandı. 500 hatası tamamen ortadan kalktı.

### 4. Sonuç ve Öneriler
- Vite konfigurasyon ayarları değiştirildiğinde Vite dev server konteynerinin mutlaka yeniden başlatılması gerektiği unutulmamalıdır.
- "Sessiz 500 Hataları"nda (Laravel logunun boş olduğu durumlarda) Docker üzerindeki Node ve Web sunucu (Nginx/PHP-FPM) loglarının mutlaka ilk kontrol edilmesi gereken yer olduğu teyit edilmiştir.
